## 低延迟图传与后续钢珠识别

- 2026-08-03 针对图传延迟完成第一阶段优化：摄像头输入队列和预留的识别后图传队列长度均改为 1，摄像头任务采用非阻塞投递，队列满时归还旧帧并只保留最新帧。
- 摄像头保持 `PIXFORMAT_RGB565 + FRAMESIZE_QVGA (320x240)`，避免影响后续钢珠识别；帧缓冲从 2 个增加为 3 个，并改用 `CAMERA_GRAB_LATEST`。
- 网页图传的软件 JPEG 质量从 80 调整为 60，这只影响网页画面压缩，不改变识别任务接收的原始 RGB565 数据。
- MJPEG 响应增加禁止缓存头，声明帧率改为 20，并在每帧头中增加 `X-Frame-Age`，用于测量从摄像头时间戳到开始发送的帧龄。
- 后续推荐链路：摄像头最新帧队列 -> 钢珠识别和坐标更新 -> 非阻塞投递最新预览帧 -> HTTP 图传。坐标识别必须独立于网页是否连接，网页队列满时只能丢预览帧，不能阻塞识别任务。
- 第二阶段在 HTTP 图传端增加固定二倍最近邻降采样：识别输入继续使用 `320x240 RGB565` 原图，只有网页预览在软件 JPEG 编码前缩小为 `160x120`。每个流连接复用一块 38400 字节 PSRAM 缓冲，分配失败时自动回退到原始 QVGA 编码。
- 低延迟版本已完整构建成功，`build/Camera_Display.bin` 大小为 `0xf4890` 字节（1001616 字节），最小应用分区剩余 74%。
- `COM34` 已确认是 ESP32-S3 revision v0.2、2 MB PSRAM，并已成功烧录；Bootloader、分区表、应用镜像均通过 Hash 校验。
- 单客户端采集 30 帧实测：JPEG 尺寸为 `160x120`，`X-Frame-Age` 最小 106 ms、平均 111 ms、P95 144 ms、最大 147 ms，采集间隔平均 79.6 ms，接收帧率 13.7 FPS，JPEG 平均 1823 字节。
- 相比 QVGA 软件 JPEG 基线（平均帧龄 201.8 ms、P95 236 ms），平均帧龄下降约 45%，P95 下降约 39%；该优化不降低后续钢珠识别的原图分辨率。
- 实机主页仍显示 `Record MP4`，包含 `video/mp4` 逻辑且不含 WebM；由于录制 Canvas 跟随 MJPEG 自然尺寸，当前导出的监控视频为 `160x120`，不影响识别支路使用 QVGA 原图。
